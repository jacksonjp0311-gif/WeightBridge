# Prospective protected-stage host helper v3

This is supplemental host orchestration outside the 162 frozen Phase S scientific source files. It does not change datasets, models, learning, scoring, acceptance criteria or numerical budgets. It was pinned, synthetically tested and independently reviewed before any protected action. V1 and V2 are preserved as unrun superseded proposals.

The host exposes four explicit actions per locked finalist: historical-retention, qualification, confirmation, and finalize. Nothing runs on import. Model workers use the frozen S evaluator and the shared execution ledger. No automatic protected evaluation is authorized by this publication. The operator runs one explicit hash-bound private request at a time after both arms have locked their finalist or terminal decisions.

## Closed evidence transactions

Historical retention must have a completed, unfailed enclosing transaction. Its exact bridge request, source, recorded worker comparisons, fresh native replays and physical checkpoint paths are independently recomputed before a new bank opens. Qualification must likewise complete, pass and reproduce before confirmation. Final PASS requires both complete formal transactions with exact gate, replay, request, started-record, protocol, source and checkpoint identities. A partial gate or replay cannot substitute for a completion marker. Missing stages remain null, with interruption reported as INTERRUPTED_INCOMPLETE; failed and insufficient-headroom outcomes remain failed. Failure bookkeeping does not require opening a later bank.

Shared parent references are reused only after full validation. Each published cache retains its original owner's protocol, claim, measured worker and process receipt. An unpublished or incomplete attempt remains immutable, including its execution costs. The other arm may own a separate attempt in a different directory on the same frozen bank. The failed owner cannot retry. All attempts count against the unchanged shared budget; cached reuse adds no model call and its original cost must not be counted twice. Candidate and own-parent native replay still use fresh, distinct processes and their recorded protocols. Physical --base paths are checked against the reconstructed model or actual parent as appropriate.

Historical evaluation checks the fixed 832 R Bank A presentations under the unchanged legacy decimal endpoint. It is retention evidence, not fresh generalization. R Bank B is never read. Formal qualification and confirmation use only their committed new bank. No refitting, redraw, alternative finalist, production deployment or lineage promotion is available.

## Reproduction and scope

`protected_host_selftest_v3.py --out NEW_RECEIPT.json` runs 26 synthetic authorization, interruption, ownership, physical-source and replay checks. The included receipt measured 1.207 wall seconds and 1.141 CPU seconds with no model calls or protected-roster reads. These software checks do not establish model success. The public package contains no private requests, rosters, seeds, per-row outputs, weights or optimizer states.

The script retains its original local paths so the published bytes exactly match the source pinned in host requests. A different machine needs an explicitly reviewed path adaptation and a new source hash; it must not impersonate the original driver. The source uses `python protected_host_v3.py --request PRIVATE_REQUEST.json`, where schema is `weightbridge.phase_iiis.protected_host_request.v3` and driver_sha256 must match these bytes. Private requests also identify the study, arm, unchanged shared ledger, original checkpoint and independently verified R parent. Never publish those requests with protected data.

Protected action results and measured costs will be reported separately after execution. This package is prospective code and evidence of its checks only; it contains no synthetic PASS for unopened stages.
